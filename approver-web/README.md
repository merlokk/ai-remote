# approver-web

Claude Code permission requests in a browser tab: the page lists what is waiting
on the bus and answers it with a button, instead of the console prompt in
`approver/responder.py`.

Under the requests it also shows the model and how much of the 5h / 7d rate limits
is spent, read off the same bus from the Rust status line in [`../statusline`](../statusline).

The loop is closed: register a key with a one-time token from the page, and every
allow/deny is signed so `hook.py` accepts it. The key is a **non-extractable
WebCrypto key held by the browser** — no private key on disk, not even on this
app's own server, and it survives closing the browser.
Architecture and the decisions behind it: [`CLAUDE.md`](CLAUDE.md).

## Run

```powershell
cd nats; docker compose up -d   # NATS, if it is not already running
cd ../approver-web
run.cmd                         # installs on first run, then http://localhost:3000
```

`run.cmd [--prod] [--port N] [--install]` — no elevation, no venv, unlike the
scripts in `scripts\`. `copy config.example.json config.json` if you want to
change the defaults; the app runs without it.

`127.0.0.1` and this machine's LAN address work as well as `localhost` — the dev
server is told to serve its own chunks to all of them (`allowedDevOrigins` in
`next.config.ts`, with the reason). Reaching it from a phone still means putting
an unauthenticated approve button on the network; see [`CLAUDE.md`](CLAUDE.md).

Then register the page as a responder — mint a token and paste it into the
`Register` panel, below the requests:

```powershell
py approver\registration_handler.py --get-token approver-web   # prints the token
py approver\registration_handler.py                            # leave it listening
```

A second browser needs its own token under its own name
(`--get-token approver-web-phone`): one `key_id` holds one key, so re-using the
first token rotates the first browser out instead of adding to it. Registered
this way, both answer under their own names.

Open the page and leave it open: having it open *is* being a responder. It
subscribes to `approvals.*` in the `approvers` queue group, so **run only one
responder at a time** — with `responder_yubikey.py` also up, each request goes to
exactly one of them, arbitrarily.

## Checks

```powershell
npm test        # protocol parity against vectors generated by approver/protocol.py
npm run build   # type-checks the app and the tests
```

And from the repository root, the tier that needs a browser because the key is
inside one — register, request, click, and `hook.verify_reply` on the answer:

```powershell
scripts\web-approval.cmd    # ~35s, unattended; needs NATS and `agent-browser`
```

Stack: Next.js (app router) · Chakra UI · React Hook Form + Zod ·
`@nats-io/transport-node` · `node:test` for tests (no runner dependency).
